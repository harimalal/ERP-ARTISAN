ARTEASY — Session dev 21 août 2026

Import de données : de 2h de saisie à un simple glisser-déposer

Comment l'onboarding Admin d'ARTEASY est passé d'un import Excel à colonnes fixes à un import universel piloté par IA — sans changer l'architecture, en changeant uniquement la façon d'y faire entrer les données.

Le problème

On demandait à l'artisan de devenir opérateur de saisie

Avant

6 fichiers Excel différents, un par type de donnée (clients, fournisseurs, articles, produits, recettes, commandes). Colonnes figées, zéro tolérance de format.

Conséquence mesurée

Plus de 2 heures de saisie pour un onboarding complet — testé et chronométré par l'utilisateur lui-même avant ce chantier.

La demande initiale

Un seul geste : déposer ce qu'on a déjà

PDF, photo, Excel, peu importe le format. L'IA scanne, catégorise et importe automatiquement — l'utilisateur ne présélectionne jamais le type de document à l'avance.

Architecture

Le pipeline en 4 étapes

  1. Tri déterministe — fichier déjà conforme à un ancien modèle → import direct, zéro IA, zéro coût.
  2. Scan IA — un appel par fichier, catégorisation + extraction en une seule fois, même sur un classeur multi-onglets.
  3. Dédoublonnage déterministe — jamais laissé à l'IA, comparé à l'existant et au reste du lot déposé.
  4. Validation humaine ciblée — seuls les cas ambigus ou à confiance basse demandent un clic.
Décision d'architecture

Résilience sans sur-ingénierie

Le navigateur pilote le scan, mais chaque résultat de fichier est écrit immédiatement en base — un incident réseau pendant un lot de 30 fichiers ne fait perdre que le fichier en cours, jamais le travail déjà fait.

Écarté volontairement : un vrai système de job serveur asynchrone — complexité disproportionnée pour un usage ponctuel (l'onboarding arrive une fois par client, pas au quotidien).

Méthode de développement

17 tâches, un implémenteur + un reviewer par tâche

Chaque étape du pipeline a été développée par un agent frais, puis vérifiée indépendamment par un second agent avant d'être considérée terminée — sur une branche isolée, jamais directement sur le code de production.

Ce que la revue de code a trouvé

Une régression détectée avant qu'elle ne parte en prod

"Le premier scan gratuit d'un nouveau client ne s'appliquait en réalité jamais — marqué comme utilisé avant même le scan, pas après."

Trouvé par la revue finale de branche, sur le modèle le plus capable, avant tout déploiement — corrigé le jour même, avec re-vérification indépendante du correctif.

Ce que le code seul n'aurait jamais vu

Le premier test réel a trouvé ce qu'aucune revue n'avait vu

"Recliquer sur 'Importer' après un échec partiel recréait les données déjà importées avec succès."

20 fichiers de test générés pour un chocolatier fictif — cas ambigus, doublons volontaires, cellules Excel piégées. Le bug de duplication n'existait sur aucun cas simulé en code : il dépendait d'un vrai comportement utilisateur, imprévisible sur le papier.

Sécurité des données

Supprimer un doublon, jamais en un clic aveugle

L'outil de nettoyage des doublons ajouté après le premier test propose toujours un écran de revue, garde le plus ancien par défaut, et s'appuie sur les vraies contraintes de la base — si un doublon est déjà lié à une commande, la suppression échoue proprement plutôt que d'emporter des données liées.

Avant / après

Ce qui change pour l'artisan

Avant

6 modèles Excel imposés. Format exact obligatoire. 2h+ de saisie manuelle.

Après

Glisser-déposer n'importe quel fichier existant, même en vrac. L'IA catégorise. Un clic seulement quand c'est vraiment ambigu.

L'architecture de l'administration n'a pas changé — mêmes fiches client, fournisseur, article, produit. Seule la porte d'entrée a changé.

Point ouvert à suivre dans le temps : le plafond de 30 fichiers par lot du premier scan gratuit — suffisant, ou à ajuster une fois des clients réels à gros volume connectés.

Le principe à retenir

Un logiciel s'adapte à l'utilisateur, pas l'inverse

Quand un import de données impose son propre format à l'utilisateur, c'est le logiciel qui doit changer. L'IA rend ce genre de refonte possible aujourd'hui d'une façon qui n'existait pas il y a deux ans.
