Le contexte

Une plateforme ERP artisan avec 4 phases en 3 jours

ARTEASY est une plateforme Netlify + Supabase pour que les artisans gèrent stocks, commandes, production, factures sans interface complexe. La dernière semaine (21-22 août) a concentré 4 sessions parallèles : stabiliser le flux commande→facturation, implémenter un onboarding IA universel, améliorer l'UX visuelle, et décider la prochaine direction design. Le résultat : deux features majeures en production, 16 bugs corrigés, 34 captures vidéo, et un playbook complet pour la prochaine session.

Zoom Session 1

6 bugs trouvés & corrigés — du plus simple au plus grave

1
Production.js : collision références
Client générait BC/FAC côté JS → garantissait doublon au 1re facture auto. Fix : migrate vers numération serveur.
2
Migration compteurs vide
Aucune seed depuis historique → 1re commande plantait pour tout tenant avec historique. Fix : migration corrective idempotente.
3
SIRET client jamais sauvegardé
Champ dans le form mais jamais envoyé à updateClient. Fix : ajout au payload.
4
Facture manuelle échouait 100%
Colonne notes inexistante en base → INSERT échouait silencieusement. Fix : retrait du champ.
5
TVA mixte surfacturait (!!)
Math.max au lieu de pondérée → facture à 2 taux TVA surfacturait le client. Trouvé en filmant démo, pas en lisant le code. Fix : taux effectif pondéré + ventilation PDF.
6
Statut commande jamais persisté
Après clôture d'un OF, le statut "prêt" revenait jamais en base. Bouton Livrer n'apparaissait jamais. Fix : appel updateCommandeStatut.
Zoom Session 2

10 bugs trouvés en revue + 1 en test réel — robustesse prompt IA critique

Revue de code (tâche-level)

Excel multi-onglets ignorés · Fix dates cassait parsing · Inaccessibilité import · Compteur mal placé · Vérif tenantId manquante · Confiance basse silencieuse

Revue finale + test réel

Suppression inconditionnelle lot d'erreurs · Reclic recréait entités déjà créées (statut importe vs confirme) · Catégories non contraintes · Dédoublonnage trop agressif

Pattern clé : Un audit de prompt dédié a trouvé 3 faiblesses que nulle revue de code n'aurait vues : définitions métier absentes, pas d'instruction "une ligne = une entité", max_tokens insuffisant. À réappliquer : toujours passer les prompts IA par une revue séparée du code.
